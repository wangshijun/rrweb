# Using Plugins

The rrweb plugin API is designed to extend the core functionalities of rrweb without increasing the complexity and bundle size of the main package. Plugins allow you to capture additional data during recording or introduce custom behaviors during replay, tailoring the session reconstruction process to your specific needs.

This guide provides a general overview of how to integrate and configure plugins for both recording and replaying sessions.

## Available Official Plugins

rrweb offers several official plugins to handle common use cases. Here are the currently available plugins:

| Plugin Package | Description |
| :--- | :--- |
| `@rrweb/rrweb-plugin-console-record` | A plugin for recording browser console log outputs. |
| `@rrweb/rrweb-plugin-console-replay` | A plugin for replaying the captured console logs. |
| `@rrweb/rrweb-plugin-sequential-id-record` | A plugin for assigning sequential IDs to events during recording. |
| `@rrweb/rrweb-plugin-sequential-id-replay` | A plugin for handling sequential IDs during replay. |
| `@rrweb/rrweb-plugin-canvas-webrtc-record` | A plugin to stream `<canvas>` animations via WebRTC for efficient recording. |
| `@rrweb/rrweb-plugin-canvas-webrtc-replay` | A plugin to replay `<canvas>` animations streamed via WebRTC. |

## Integrating Plugins

Plugins are integrated separately for the recording and replaying processes, as they serve different purposes.

### For Recording

To use a recording plugin, pass an array of plugin instances to the `plugins` option in the `rrweb.record()` configuration.

```javascript title="Integrating a record plugin" icon=logos:javascript
rrweb.record({
  emit: (event) => {
    // a custom emit function
  },
  plugins: [yourRecordPlugin],
});
```

#### RecordPlugin Interface

A record plugin is an object that conforms to the `RecordPlugin` interface.

<x-field-group>
  <x-field data-name="name" data-type="string" data-required="true" data-desc="A unique name for the plugin. This name is stored in the events emitted by the plugin."></x-field>
  <x-field data-name="observer" data-type="(cb: Function, options: TOptions) => listenerHandler" data-required="true" data-desc="The core logic of the plugin. This function receives a callback `cb` to emit custom events and the plugin's `options`."></x-field>
  <x-field data-name="options" data-type="TOptions" data-required="true" data-desc="Configuration options specific to the plugin."></x-field>
</x-field-group>

#### Example: Custom Record Plugin

Here is an example of a simple record plugin that emits a custom event with a timestamp every second.

```javascript title="exampleRecordPlugin.js" icon=logos:javascript
const exampleRecordPlugin = {
  name: 'my-scope/example@1',
  observer(cb, options) {
    const timer = setInterval(() => {
      cb({
        foo: options.foo,
        timestamp: Date.now(),
      });
    }, 1000);
    // Return a function to stop the observer
    return () => clearInterval(timer);
  },
  options: {
    foo: 'bar',
  },
};

rrweb.record({
  emit(event) {
    console.log(event);
  },
  plugins: [exampleRecordPlugin],
});
```

This plugin will generate events with a `type` of `6` (Plugin), containing the plugin's name and its custom payload.

```json title="Example plugin event output"
{
  "type": 6,
  "data": {
    "plugin": "my-scope/example@1",
    "payload": {
      "foo": "bar",
      "timestamp": 1624693882345
    }
  },
  "timestamp": 1624693882345
}
```

### For Replaying

Replay plugins are integrated by passing them to the `plugins` option in the `rrweb.Replayer` constructor.

```javascript title="Integrating a replay plugin" icon=logos:javascript
const replayer = new rrweb.Replayer(events, {
  plugins: [yourReplayPlugin],
});
```

#### ReplayPlugin Interface

A replay plugin is an object that can implement one or more methods to interact with the replayer's lifecycle.

<x-field-group>
  <x-field data-name="handler" data-type="(event, isSync, context) => void" data-required="false" data-desc="A function that is called for each event during replay. It allows you to process custom plugin events."></x-field>
  <x-field data-name="onBuild" data-type="(node, context) => void" data-required="false" data-desc="A callback that fires when a DOM node is built in the replayer's iframe."></x-field>
  <x-field data-name="getMirror" data-type="(mirrors) => void" data-required="false" data-desc="A function to get access to the replayer's internal mapping between node IDs and actual DOM nodes."></x-field>
</x-field-group>

#### Example: Custom Replay Plugin

This example demonstrates a replay plugin that listens for events generated by the `my-scope/example@1` recording plugin.

```javascript title="exampleReplayPlugin.js" icon=logos:javascript
import { EventType } from 'rrweb';

const exampleReplayPlugin = {
  handler(event, isSync, context) {
    if (
      event.type === EventType.Plugin &&
      event.data.plugin === 'my-scope/example@1'
    ) {
      // handle the custom plugin data from the payload
      console.log('Custom plugin event received:', event.data.payload);
      // You can also interact with the replayer instance via context.replayer
    }
  },
};

const replayer = new rrweb.Replayer(events, {
  plugins: [exampleReplayPlugin],
});
```

The `handler` function checks for custom plugin events and allows you to execute logic based on their payload. The `context` object provides access to the `replayer` instance for more advanced interactions.

## Plugin Naming Convention

To prevent naming conflicts between official `rrweb` plugins and custom plugins developed by users, a standardized naming convention is strongly recommended. This ensures that event data can be correctly attributed to its source plugin.

The recommended format is:

> `scope/name@version`

For example:
- `rrweb/console@1`
- `my-company/feature-tracker@2.1`

Adhering to this convention will help maintain a clean and manageable implementation as you integrate more plugins.
